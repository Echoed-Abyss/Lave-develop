# 后台保活

机器人要在后台一直在线，就必须解决一个具体的问题：
**应用退到后台后，进程会被系统冻结，心跳发不出去，服务端于是关闭连接。**

这一页说明本项目怎么解决它，以及哪些情况**解决不了**——后面这部分同样重要，
省得你把平台的硬限制当成 bug 反复折腾。

## 症状长什么样

- 日志反复出现「连接被关闭：1002」；
- 每次连接只活几十秒到两分钟——这正好是 1~3 个心跳周期（41.25 秒）；
- 断连时应用都不在前台。

## 根因

这里有**两条互相独立**的原因，只解决其中一条都还会掉线：

**① 进程被冻结。** 应用退到后台后进程进入 **cached 状态**，Android 的
**cached apps freezer 会在约 10 秒后冻结该进程**。被冻结时 Dart 的定时器
不再触发，心跳停发，服务端随即关闭连接。

官方给出的解药就是把进程**移出 cached 状态**：前台服务的进程属于「可见进程」，
不会被冻结。而 Dart 侧无法自行改变进程优先级，必须由原生侧起一个真正的前台服务。

**② Flutter 引擎随 Activity 一起被销毁。** 这一条更隐蔽，也更容易被误判：
Dart 代码活在 `FlutterEngine` 里，而 `FlutterActivity` **默认会把引擎与 Activity
同生共死**。用户从最近任务划掉应用、或系统在内存紧张时回收 Activity，都会让
引擎连同 Dart 的运行环境一起消失——此时前台服务还活着、进程也还活着，
**只有 Dart 死了**，于是定时器不再运行、socket 被关闭。

所以只做前台服务是不够的。本项目在 `MainActivity` 里额外做了两件事：

- `provideFlutterEngine()` 返回**同一个**引擎实例，首次创建后一直复用；
- `shouldDestroyEngineWithHost()` 返回 `false`，Activity 销毁时不动引擎。

于是 Activity 退出后 Dart 继续运行、心跳照发、连接保持，前台服务负责进程不被冻结。
重新打开应用时引擎被重新挂到新 Activity 上，界面直接接上仍在运行的连接。

## 五条互相兜底的路径

| 手段 | 覆盖的故障场景 | 依据 |
| --- | --- | --- |
| 前台服务（`startForeground`） | 进程进入 cached 状态后被冻结 | 前台服务进程属「可见进程」，不进 cached 列表 |
| `PARTIAL_WAKE_LOCK` | 息屏后 CPU 停止调度，心跳发不出去 | 前台服务只改进程优先级，不阻止休眠 |
| `START_STICKY` + 15 分钟看门狗闹钟 | 系统因内存压力回收进程 | 系统会重建服务；闹钟负责在重建失败时再拉一次 |
| `onTaskRemoved` + 精确闹钟 | 用户从最近任务划掉应用 | Android 12+ 的后台启动豁免清单里含「精确闹钟」 |
| 开机广播（`BOOT_COMPLETED` 等） | 手机重启 | 同一个豁免清单里含开机广播 |

### 为什么前台服务类型选 `specialUse`

Android 14 起每个前台服务必须声明类型。类型选错会让保活**在特定版本上失效**：

- `dataSync`：Android 15 起，24 小时内累计只能运行 **6 小时**，
  到点系统要求停服，之后除非用户把应用切回前台，否则无法再次启动。
  对「应当 24 小时在线」的机器人客户端是致命的；
- **`specialUse` 没有时长限制**，因此 API 34+ 用它；
- API 31~33 还没有 `specialUse` 类型，退回 `dataSync`。

另外 Android 15 起开机广播**不允许**拉起 `dataSync` 类型（会抛异常），
但允许 `specialUse`——这也是必须选它的原因之一。

### 被系统掐掉时会发生什么

Android 15（API 35）起，`dataSync` / `mediaProcessing` 这两类前台服务会被系统
按运行时长配额掐掉，并通过 `Service.onTimeout(int, int)` 通知应用。应用**必须**
在这个回调里主动停服，否则会被判 ANR 并丢掉前台资格。

本项目在 API 34+ 一律用无时限的 `specialUse`，正常情况下这个回调永远不会触发；
但仍然完整实现了它，并做了两件事：

1. 如实把那行「因类型配额被停服」写进系统日志，而不是假装还在线；
2. 停服并交给看门狗闹钟在允许的时机重新拉起。

同时设置页会把**实际生效的前台服务类型**显示出来。如果那里显示的是 `dataSync`
（而不是 `specialUse`），说明系统拒绝了 `specialUse` 类型，
这种情况在「开机几小时后必掉线」的现场里很常见——有了这一行就能一眼定性。

## 退出应用 ≠ 停止机器人

只要「后台保活」开关是开的，**退出应用不会让机器人下线**：连接、插件与常驻通知
都会继续运行。这正是「保活」这个功能的含义——如果退出即等于下线，
那这个开关就没有意义。

要真正停下来，有两个明确入口：

- 应用内「设置 → 后台保活 → 保活前台服务」开关关掉；
- 常驻通知上的 **「停止保活」** 按钮。

两者都会同时撤掉看门狗闹钟，因此不会出现「点了停止、过一会儿又被自动拉起来」。

反过来，如果保活开关是关的，退出应用就做完整收尾：停连接、结束插件子进程、
撤掉常驻通知。不会留下孤儿进程，也不会留下一条内容与事实不符的通知。

## 为什么不用 JobScheduler

这是个常见误解：**作业执行不在前台服务后台启动的豁免清单里**。
JobScheduler 可以在后台做定时工作，但**不能凭它去启动一个前台服务**——
会被系统拒绝。真正有效的定时手段只有精确闹钟。

### 精确闹钟需要单独授权

Android 14 起该权限默认被拒绝。设置页「后台保活」里有授权入口
（跳系统「闹钟和提醒」页）。未授权时会自动退回不精确闹钟——仍会响，
但系统会按省电策略推迟，因此「被清掉后能不能自己回来」差别很大。

## 通知能被用户划掉吗

| 版本 | 行为 |
| --- | --- |
| Android 12 / 13 | `setOngoing(true)` 已足够，用户划不掉 |
| **Android 14 及以上** | **系统改了行为，`setOngoing(true)` 也挡不住**（锁屏界面与「全部清除」除外） |

这是官方行为变更，应用无法对抗。**通知被划掉不影响服务运行**，
只是用户看不到在线状态。

本项目刻意**不**用通话样式（`CallStyle`）或媒体通知去换「通知不可关闭」：
那是把长连接伪装成来电，属于欺骗性 UI。用用户信任换一个「不可关闭」的小便利，
不划算。

用户关闭通知渠道或拒绝通知权限，同样只是让通知不可见，前台服务照常运行。

## 两种无法对抗的操作

::: danger 这两件事之后，任何自动拉起都会失效

1. **「强行停止」**（设置 → 应用 → 强制停止）；
2. **任务管理器里点「停止」**（通知栏底部的「使用中的应用」）。

两者都会让应用进入 **stopped 状态**，之后连开机广播都收不到，
只能由用户重新打开应用。这是 Android 的既定行为，任何应用都无法绕过。

:::

## 电池优化白名单

低电耗模式（Doze）生效后，系统会**暂停应用的网络访问**并**忽略唤醒锁**。
注意这条与前台服务是**两条独立的限制**：前台服务只让进程不被冻结，
挡不住 Doze 掐网络——所以「白天正常、放一晚上必掉线」往往是这里的问题。

设置 → 后台保活 → 「电池优化」一行，点一下就会弹出系统的
「是否允许应用在后台运行」对话框，选「允许」即可。

应用声明了 `REQUEST_IGNORE_BATTERY_OPTIMIZATIONS`。官方对该权限的用途限制很严
（只接受「Doze 破坏了核心功能且技术上无法改用 FCM」）；本应用是自建 WSS 长连接、
不上架应用商店、由用户自行安装，且**由用户主动点击才触发系统弹窗**，
应用不会私自申请。个别 ROM 会拦截这个动作，那时会自动退回系统设置列表页。

## 待机分桶

Android 9 起系统会按使用频率把每个应用丢进一个「待机分桶」。
**从「极少使用」（RARE，取值 40）这一档开始，系统会限制应用的互联网连接**——
这与前台服务在不在跑无关，是独立的第三条掉线原因。

| 取值 | 分桶 | 对后台网络的影响 |
| --- | --- | --- |
| 10 | 活跃 | 基本无限制 |
| 20 | 工作集 | 轻微限制（仅作业与闹钟） |
| 30 | 常用 | 较高限制（仅作业与闹钟） |
| 40 | 极少使用 | **系统会限制互联网连接** |
| 50 | 受限 | 限制最严，每天只能跑一次作业与会话 |

设置页会直接显示当前分桶。要脱离低优先级分桶，最直接的办法是把电池优化设为
「不优化」，以及多打开几次应用。

## 国产 ROM

小米 / 华为 / OPPO / vivo 等 ROM 的省电策略差异很大，可能需要额外在系统设置里
允许「自启动」与「后台运行」。应用只能把该做的都做完，剩下的取决于系统。

## 怎么看保活到底生效了没有

设置页「后台保活」里的五行状态是**实时查询**的系统事实，不是开关的镜像：

| 行 | 含义 | 不合格的后果 |
| --- | --- | --- |
| 服务状态 | 前台服务是否真的以前台形态在跑 | 进程会被冻结，连接几十秒内必断 |
| 服务类型 | 实际生效的类型（`specialUse` / `dataSync`） | 落到 `dataSync` 时每 24 小时只剩 6 小时 |
| 电池优化 | 是否已加入白名单 | Doze 会暂停网络访问 |
| 精确闹钟 | 是否已获得精确闹钟权限 | 被系统清掉后无法自己回来 |
| 待机分桶 | 应用当前所处的分桶 | RARE 起系统限制互联网连接 |

只给开关不给事实的话，用户遇到「开关是开的、但机器人就是不在线」时
没有任何排查方向——这五行就是为了把这个死胡同打开。
