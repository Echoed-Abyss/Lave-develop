# 后台保活

机器人要在后台一直在线，就必须解决一个具体的问题：
**应用退到后台后，进程会被系统冻结，心跳发不出去，服务端于是关闭连接。**

这一页说明本项目怎么解决它，以及哪些情况**解决不了**——后面这部分同样重要，
省得你把平台的硬限制当成 bug 反复折腾。

## 症状长什么样

- 日志反复出现「连接被关闭：1002」；
- 每次连接只活几十秒到两分钟——这正好是 1~3 个心跳周期（41.25 秒）；
- 断连时应用都不在前台。

## 根因

应用退到后台后进程进入 **cached 状态**，Android 的
**cached apps freezer 会在约 10 秒后冻结该进程**。被冻结时 Dart 的定时器
不再触发，心跳停发，服务端随即关闭连接。

官方给出的解药就是把进程**移出 cached 状态**：前台服务的进程属于「可见进程」，
不会被冻结。而 Dart 侧无法自行改变进程优先级，必须由原生侧起一个真正的前台服务。

## 五条互相兜底的路径

| 手段 | 覆盖的故障场景 | 依据 |
| --- | --- | --- |
| 前台服务（`startForeground`） | 进程进入 cached 状态后被冻结 | 前台服务进程属「可见进程」，不进 cached 列表 |
| `PARTIAL_WAKE_LOCK` | 息屏后 CPU 停止调度，心跳发不出去 | 前台服务只改进程优先级，不阻止休眠 |
| `START_STICKY` + 15 分钟看门狗闹钟 | 系统因内存压力回收进程 | 系统会重建服务；闹钟负责在重建失败时再拉一次 |
| `onTaskRemoved` + 精确闹钟 | 用户从最近任务划掉应用 | Android 12+ 的后台启动豁免清单里含「精确闹钟」 |
| 开机广播（`BOOT_COMPLETED` 等） | 手机重启 | 同一个豁免清单里含开机广播 |

### 为什么前台服务类型选 `specialUse`

Android 14 起每个前台服务必须声明类型。类型选错会让保活**在特定版本上失效**：

- `dataSync`：Android 15 起，24 小时内累计只能运行 **6 小时**，
  到点系统要求停服，之后除非用户把应用切回前台，否则无法再次启动。
  对「应当 24 小时在线」的机器人客户端是致命的；
- **`specialUse` 没有时长限制**，因此 API 34+ 用它；
- API 31~33 还没有 `specialUse` 类型，退回 `dataSync`。

另外 Android 15 起开机广播**不允许**拉起 `dataSync` 类型（会抛异常），
但允许 `specialUse`——这也是必须选它的原因之一。

### 为什么不用 JobScheduler

这是个常见误解：**作业执行不在前台服务后台启动的豁免清单里**。
JobScheduler 可以在后台做定时工作，但**不能凭它去启动一个前台服务**——
会被系统拒绝。真正有效的定时手段只有精确闹钟。

### 精确闹钟需要单独授权

Android 14 起该权限默认被拒绝。设置页「后台保活」里有授权入口
（跳系统「闹钟和提醒」页）。未授权时会自动退回不精确闹钟——仍会响，
但系统会按省电策略推迟，因此「被清掉后能不能自己回来」差别很大。

## 通知能被用户划掉吗

| 版本 | 行为 |
| --- | --- |
| Android 12 / 13 | `setOngoing(true)` 已足够，用户划不掉 |
| **Android 14 及以上** | **系统改了行为，`setOngoing(true)` 也挡不住**（锁屏界面与「全部清除」除外） |

这是官方行为变更，应用无法对抗。**通知被划掉不影响服务运行**，
只是用户看不到在线状态。

本项目刻意**不**用通话样式（`CallStyle`）或媒体通知去换「通知不可关闭」：
那是把长连接伪装成来电，属于欺骗性 UI。用用户信任换一个「不可关闭」的小便利，
不划算。

用户关闭通知渠道或拒绝通知权限，同样只是让通知不可见，前台服务照常运行。

## 两种无法对抗的操作

!!! danger "这两件事之后，任何自动拉起都会失效"

    1. **「强行停止」**（设置 → 应用 → 强制停止）；
    2. **任务管理器里点「停止」**（通知栏底部的「使用中的应用」）。

    两者都会让应用进入 **stopped 状态**，之后连开机广播都收不到，
    只能由用户重新打开应用。这是 Android 的既定行为，任何应用都无法绕过。

## 电池优化白名单

低电耗模式（Doze）会**忽略唤醒锁**并暂停网络访问，因此彻底解决需要用户手动加白：

设置 → 后台保活 → 电池优化 → 点「未加白名单，点此设置」。

应用**不申请** `REQUEST_IGNORE_BATTERY_OPTIMIZATIONS` 权限：官方对该权限的用途
限制很严（只有「Doze 破坏了核心功能且技术上无法改用 FCM」才被接受），
本项目只跳到系统设置页让用户自己加，不背这个受限权限。

## 国产 ROM

小米 / 华为 / OPPO / vivo 等 ROM 的省电策略差异很大，可能需要额外在系统设置里
允许「自启动」与「后台运行」。应用只能把该做的都做完，剩下的取决于系统。

## 怎么看保活到底生效了没有

设置页「后台保活」里的三项状态是**实时查询**的系统事实，不是开关的镜像：

| 行 | 含义 |
| --- | --- |
| 服务状态 | 前台服务是否真的以前台形态在跑 |
| 精确闹钟 | 是否已获得精确闹钟权限 |
| 电池优化 | 是否已加入白名单 |

只给开关不给事实的话，用户遇到「开关是开的、但机器人就是不在线」时
没有任何排查方向。
