# 安装与首次配置

## 环境要求

| 项目 | 要求 |
| --- | --- |
| Android | **12 ~ 16**（API 31 ~ 36）。低于 12 装不上：保活的每条路径都依赖 Android 12 起才有明确语义的后台启动规则 |
| 架构 | `arm64-v8a`（近年的真机基本都是） |
| 网络 | 需能访问 `api.bot.qq.com` 与 `q.qlogo.cn` |
| 存储 | 约 60MB（APK 22.4MB + 内置 Python 运行时释放后的标准库） |

模拟器（`x86_64`）**不在支持范围内**：内置的 Python 运行时只打包了 `arm64-v8a`，
在模拟器上插件会显示「未能检测到内置 Python 运行时」。

## 安装

从 [GitHub Releases](https://github.com/Echoed-Abyss/Lave-develop/releases)
或仓库根目录的 `build/app/outputs/flutter-apk/app-release.apk` 取 APK 安装。

首次安装后建议按 [后台保活](../guide/keep-alive.md) 里的说明把应用加入
**电池优化白名单**：低电耗模式（Doze）会暂停网络并忽略唤醒锁，
不加白名单的话息屏久了机器人仍可能掉线。

## 在开放平台准备机器人

1. 打开 [QQ 机器人开放平台](https://q.qq.com/) 并创建机器人；
2. 在「开发设置」里记下 **机器人 ID**（就是 AppID）与 **AppSecret**；
3. 在「功能配置」里**必须开通**「单聊消息」与「群聊消息」权限，
   否则连上了也收不到任何消息（见 [intents](../reference/intents.md)）；
4. 把机器人拉进一个测试群，或先加为好友用于单聊测试。

::: warning AppSecret 只显示一次

平台只在创建时完整显示 AppSecret，之后只能重置。
重置会让已经运行的实例全部掉线，因此请当场存好。

:::

## 在应用里添加机器人

打开应用 → 「机器人」页 → 右下角「添加机器人」：

| 字段 | 填什么 | 说明 |
| --- | --- | --- |
| **AppID** | 平台上的机器人 ID | 作为本地账号主键，**添加后不可修改** |
| **备注名** | 随便填 | 留空则显示官方昵称（启动后会去拉） |
| **AppSecret** | 平台给的密钥 | 用于换取 `access_token`，应用会自动续期 |
| **Bot Token** | 可选 | 官方标注「已弃用」，仅在 Identify 的另一种拼法下需要 |
| **Identify 的 token 拼法** | 保持默认 | 官方两处文档口径不一致，故做成可切换项，见下 |

保存后应用会立刻尝试连接。连接成功的标志是「机器人」页卡片上的状态变成**在线**，
并且「日志」页出现「鉴权成功，已进入在线状态」。

### 关于 Identify 的 token 拼法

官方文档存在**口径冲突**（`知识库` 11.1 节）：字段表写 `QQBot {AccessToken}`，
另一页正文写 `Bot {appid}.{app_token}`。本项目把拼法做成账号上的可切换项，
默认用字段表口径。若连接被拒且错误码不指向 token，可以切到另一种拼法再试——
总比把某一种拼法写死在代码里、然后花几个小时怀疑密钥错了要好。

## 关于密钥存放

密钥保存在系统的安全存储里（Android 使用 Keystore 加密的 SharedPreferences），
不会写入普通数据库，日志里也做了脱敏。但请清楚这条边界：

::: danger 不要在共享设备上使用

官方明确建议「不要在客户端使用访问凭证」，因为客户端持有的密钥无法抵御
设备被 root 或应用被反编译。本项目的定位是**自用与内测**，
在你自己掌控的设备上运行没有问题，但不要装在别人能接触到的设备上。

:::

应用的 `allowBackup` 已关闭：否则系统云备份还原后，
`flutter_secure_storage` 会抛 `InvalidKeyException`，
用户表现为「凭证突然读不出来」——这是官方插件文档里明确列出的坑。
