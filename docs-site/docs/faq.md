# 常见问题

## 这是什么？和别的 QQ 机器人框架有什么区别？

Lave 是一个**跑在手机上的 QQ 机器人客户端**：它直连腾讯官方网关收事件、直连官方
HTTP 接口发消息，**不需要服务器、不需要自建后端**。

区别在于定位：别的框架面向「部署在服务器上、长期运行、深度定制」；
Lave 面向「我有一台闲置手机，想让机器人一直在线，顺便能写点自己的逻辑」。

代价是它继承了移动端的所有限制：系统会杀后台、iOS 不能跑插件、
应用私有目录不好访问。这些限制在文档里都写明了。

## 会不会封号？

本项目只使用官方文档公开的接口，不使用任何逆向或模拟登录手段。
但请明确两点：

1. **凭证存在客户端**。官方建议不要在客户端使用访问凭证；
   本项目定位是自用与内测，请勿在共享设备上使用。
2. **官方有封禁机制**。网关关闭码 `4914`（机器人已下架，只允许连沙箱环境）
   与 `4915`（机器人已封禁）就是它的表现。触发原因取决于你的机器人行为，
   不取决于这个客户端。

## 为什么 iOS 不能跑插件？

`dart:io` 的 `Process.start` 在 iOS 上不可用。这是 Dart 运行平台的限制，
不是权限问题，改配置绕不开。

要在 iOS 上跑 Python 只能改为**进程内嵌解释器**（FFI 加载静态链接的 CPython），
届时 stdin/stdout 的概念不存在了，需要换成内存管道——那是另一个量级的工程量。

## 为什么只有 arm64 的插件支持？

内置的 Python 运行时按 ABI 各需一份，每份约 17.7MB。
真实手机几乎全是 `arm64-v8a`，因此只带一个架构以控制包体。
模拟器（`x86_64`）需要按[构建文档](getting-started/build.md#增加-x86-64-模拟器)自行补一份。

## 机器人明明在线，为什么群里 @ 它没反应？

按顺序排查：

1. **是不是 @ 了机器人**？群聊消息需要 @ 才会推送 `GROUP_AT_MESSAGE_CREATE`；
2. **平台权限开了吗**？「功能配置」里要开通「群聊消息」；
3. **intents 对吗**？见[故障排查](guide/troubleshooting.md#机器人连上了但收不到任何消息)；
4. **看日志有没有「群聊消息：…」**：有就说明事件到了，问题在回复侧。

## 为什么日志里消息出现了两次？

去重是按官方要求的 `message_scene.ext` 的 `msg_idx` 做的
（官方明确「相同 `msg_id` 可能重复推送」）。如果确实看到两条完全相同的消息，
请连 `msg_idx` 一起反馈——那说明官方的去重键本身重复了。

## 统计为什么不含历史消息？

统计是**按天聚合的计数器**，从本功能上线时开始累积。
历史消息存在按会话分片的仓库里，内存中每个会话最多保留 500 条，
但**落盘与恢复只保留最近 50 条**（避免重启时读写量过大）。
从那里算总量既不准也慢。详见[消息统计](guide/statistics.md)。

## 能同时跑几个机器人？

默认上限 3 个。这是 `AppConfig.maxConcurrentConnections` 的取值：
每个机器人一条独立 WSS 连接，移动端的耗电与内存随连接数线性上升。

上限可以改，但建议先评估耗电——前台服务 + 唤醒锁本来就比普通应用费电。

## 插件能发图片吗？

目前插件的 `reply` 只支持文本。发图片要走上传 + 富媒体消息两步，
而上传需要凭证——把凭证交给插件会破坏「插件拿不到 token」这条边界。
如果有明确需求，可以考虑由主程序提供一个受限的「发本地图片」请求。

## 插件能收到频道（Guild）消息吗？

不能。本项目未建模频道体系，事件分发层不认识频道事件。
这也是「频道消息带 `avatar` 却用不上」的原因。

## 为什么通知划不掉又关不掉？

见[后台保活](guide/keep-alive.md)：Android 14 起系统允许用户划掉常驻通知，
但**划掉不影响服务运行**。想彻底不看它，可以在系统设置里关闭这个通知渠道，
服务依然会跑。

## 换手机怎么迁移？

目前没有一键迁移。要搬的东西有三类：

| 内容 | 怎么搬 |
| --- | --- |
| 机器人账号与密钥 | 重新添加（密钥存在安全存储里，无法导出——这是刻意的） |
| 插件 | 每个插件点「导出」复制 JSON，在新设备上「导入插件」 |
| 消息历史 / 统计 / 日志 | 不支持迁移 |

密钥不可导出是有意为之：能导出意味着能被打包带走，而那正是最不该被带走的东西。

## 提 issue 时该带什么？

- 「日志」页右上角「复制诊断信息」导出的文本（密钥已脱敏）；
- 尽量包含失败那条日志的**官方错误码**与 **`trace_id`**——
  后者是找平台协助时唯一有效的凭据；
- 如果是插件问题，附上 `plugin.json` 与报错的那段 `main.py`。
