# 插件系统总览

插件让 Lave 从「一个机器人客户端」变成「一个能跑你自己逻辑的机器人客户端」。
这一页讲清楚它是怎么组织的、有哪些约束、以及为什么这样设计。

## 一句话

每个插件是**一个独立的 Python 进程**，通过 **stdin / stdout 上的 JSON 行协议**
与主程序通信。插件不接触任何官方接口，也不持有任何凭证。

```
   主进程（Dart）                          插件进程（Python）
   ┌──────────────┐                        ┌──────────────┐
   │ PluginManager│─── stdin: JSON 行 ────▶│  main.py     │
   │              │◀── stdout: JSON 行 ────│              │
   └──────┬───────┘                        └──────────────┘
          │ 代发消息 / 写日志 / 读配置
          ▼
   ┌──────────────┐
   │ 官方 OpenAPI │
   └──────────────┘
```

## 为什么是独立进程

| 收益 | 具体表现 |
| --- | --- |
| **崩溃隔离** | 插件抛未捕获异常 → 只有它变「已崩溃」，机器人与其它插件完全不受影响 |
| **CPU 隔离** | 插件死循环只占自己的时间片，UI 与网关连接照常 |
| **依赖自由** | 插件可以用 `subprocess`、`ctypes`、任何纯 Python 库，不必考虑与 Dart 的兼容 |
| **可强杀** | 插件卡死时可以直接结束进程，不需要它在协作式地响应取消 |

代价是跨进程通信有序列化开销、且插件拿不到内存中的对象——对本场景完全可接受。

## 安全性：插件拿不到凭证

插件**永远拿不到 `access_token`**。要发消息必须发一条 `reply` 请求，
由主程序代为调用官方接口。

这样即使插件包被替换成恶意代码，也无法直接控制机器人账号。
同理，插件也不能直接读主程序的数据目录——它只有一个专属的可写数据目录
（`init` 时下发 `data_dir`）。

## 平台能力边界

| 平台 | 能否运行插件 | 原因 |
| --- | --- | --- |
| Android（arm64-v8a） | ✅ 可以 | 内置了官方 Android 版 CPython 3.14 与一个自编启动器 |
| Android（其它 ABI） | ❌ 不可以 | 运行时只打包了 arm64-v8a |
| iOS | ❌ **不可能** | `dart:io` 的 `Process.start` 不支持 iOS。这是 Dart 运行平台的限制，改配置绕不开 |
| Windows / macOS / Linux | ✅ 可以 | 使用系统 Python（需自行安装 Python 3） |

iOS 上若要支持插件，只能改为**进程内嵌解释器**（FFI 加载静态链接的 CPython），
届时 stdin/stdout 的概念不复存在，需要换成内存管道——那是另一个量级的工程量。

## 一个插件由什么组成

```
<应用文档目录>/plugins/demo_plugin/
├── plugin.json      # 清单：身份、入口、订阅的事件、配置项声明
├── main.py          # 入口（默认名，可在清单里改）
└── data/            # 插件自己的可写目录（由主程序创建）
    └── stats.json
```

`plugin.json` 是唯一的必需文件——没有它，扫描时该目录会被跳过。

## 插件拿不到的东西

有三件事插件做不到，都是刻意的边界，写清楚比让你试出来更省事：

- **拿不到 `access_token`**：只能通过 `reply` 请求主程序代发消息。
- **读不到主程序的数据目录**：只有一个专属的可写目录（`init` 下发的 `data_dir`）。
- **不能注册内置命令**：`#help` / `#ping` / `#status` 由主程序独占。
  插件想实现「指令」就是自己比对消息前缀，见
  [内置命令与插件的边界](builtin-commands.md)。

## 怎么把插件装进手机

Android 11 起应用私有目录不再对文件管理器可见，因此本项目提供三条路径：

1. **从剪贴板导入**（插件页右下角）：复制一份插件包 JSON，粘贴即可；
2. **应用内编辑**（插件卡片 →「文件」）：直接改 `main.py`、新建文件；
3. **复制插件目录路径**，用 ADB 推送（仅调试包可用）。

插件包也可以**导出**回剪贴板，用于备份或分享。格式见
[文件与数据目录](files-and-data.md#插件包格式)。

覆盖导入同名插件时，配置与状态会被清空，导入前在跑的插件会在导入后继续跑。
理由见[文件与数据目录](files-and-data.md#覆盖导入)。
