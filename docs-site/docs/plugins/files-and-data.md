# 文件与数据目录

## 目录结构

```
<应用文档目录>/plugins/<plugin_id>/
├── plugin.json      # 清单
├── main.py          # 入口（可在清单里改）
├── helper.py        # 插件可以拆多个文件
└── data/            # ★ 插件自己的可写目录，由主程序在启动前创建
    └── cache.json
```

**代码与数据分开**是刻意的：

- 「升级插件」只是替换代码文件，用户数据不受影响；
- 删除插件时整目录一起删，不会漏掉散落的运行时文件；
- 插件不会被诱导往代码目录里写东西，那会让「重装插件」变成一件危险的事。

## 用 `data_dir`

`init` 时会下发这个目录的绝对路径，目录保证已存在：

```python
def on_init(host, payload):
    host.data_dir = payload.get("data_dir")
    if host.data_dir:
        with open(os.path.join(host.data_dir, "stats.json"), "w",
                  encoding="utf-8") as fh:
            json.dump({"started_at": time.time()}, fh)
```

::: danger 不要用相对路径

插件进程的工作目录虽然是插件目录，但那是实现细节，将来可能变。
一切文件读写都用 `data_dir` 拼绝对路径。

:::

## 在应用内管理文件

插件卡片 →「文件」：

| 操作 | 说明 |
| --- | --- |
| 查看文件列表 | 列出插件目录下的文件（**不含 `data/`**，那是运行时数据不是源码） |
| 编辑 | 打开内建编辑器，保存即写回磁盘 |
| 新建 | 在插件目录内创建文件 |
| 复制插件目录路径 | 用 ADB 推送文件时要用到（仅调试包可访问该目录） |

### 可编辑的扩展名

`.py` `.json` `.md` `.txt` `.toml` `.yaml` `.yml` `.cfg` `.ini` `.csv`，
单文件上限 512KB。

其余文件（`.pyc`、图片）会列出但不可编辑——在文本框里既看不懂也存不回去。

::: warning 改完代码要重启插件

保存只是写回磁盘。正在运行的进程加载的还是旧代码。
在卡片上点「停止」再「启动」即可。

:::

### 安全边界

所有文件操作都被限制在**插件目录之内**：

- 拒绝绝对路径；
- 拒绝含 `..` 的路径；
- 规范化之后仍不在插件目录内的路径也会被拒绝。

`plugin.json` 不能删除（删了插件就等于坏了），`entry` 指向目录外时启动会被拒绝。

这些校验不是防插件作者，而是防**插件包**——你从别处拿到的插件包里，
`plugin.json` 里的 `entry` 完全可以被写成 `../../some.py`。

## 三条安装路径

Android 11 起应用私有目录不再对文件管理器可见，所以没有「把文件复制进去」这条路：

### 从剪贴板导入（推荐）

插件页右下角「导入插件」，粘贴插件包 JSON。格式见下。

### 应用内手写

先装一次示例插件，再用「文件」把所有内容改成你的。

### ADB 推送（仅调试包）

「文件」里复制插件目录路径，然后在电脑上：

```bash
adb push ./my_plugin /data/user/0/com.echoedabyss.lavedevelop/app_flutter/plugins/my_plugin
```

注意：只有 **debug 包**能用 `adb push` 写进应用私有目录。
release 包需要 root 或 `run-as`（后者要求 debuggable）。

## 插件包格式

「导出」会把插件打包成一段 JSON 复制到剪贴板：

```json
{
  "lave_plugin_bundle": 1,
  "id": "demo_plugin",
  "files": {
    "plugin.json": "{ … }",
    "main.py": "import json\n…",
    "README.md": "# …"
  }
}
```

| 字段 | 说明 |
| --- | --- |
| `lave_plugin_bundle` | 格式版本，目前为 `1`。缺这个标记会被拒绝导入 |
| `id` | 插件 ID，同时是目标目录名 |
| `files` | 相对路径 → 文件内容（**只含文本文件**） |

### 为什么是 JSON 而不是 zip

手机上拿到 zip 之后没有可靠的解压入口，而 JSON 可以直接走剪贴板。
「复制 → 发给自己 → 在另一台设备粘贴导入」是全平台都能用的最小闭环。

代价是只能传文本文件，二进制资源（图片、模型）需要另想办法——
目前不支持，插件应尽量只依赖标准库与文本资源。

### 导入时的校验

| 校验 | 失败提示 |
| --- | --- |
| 必须是插件包 | 这不是 Lave 插件包（缺少 lave_plugin_bundle 标记） |
| `id` 合法 | 插件 ID 不合法：只允许字母、数字、下划线、连字符与点 |
| 至少有一个文件 | 插件包内没有文件 |
| 必须有 `plugin.json` | 插件包内缺少 plugin.json |
| **所有路径都安全** | 插件包内含非法路径：… |

::: info 先校验完再写盘

路径校验发生在**任何文件被写入之前**。
边校验边写的话，写到一半遇到非法路径会留下一个半成品插件目录
（有 `plugin.json` 却没有 `main.py`），而且它会出现在插件列表里——
用户会以为导入成功了。

:::

### 覆盖导入

导入一个已存在的 `id` 会**覆盖**其文件，并先停掉正在运行的旧进程。
不停止的话新旧代码会同时在跑，而界面显示的是新清单，行为对不上任何一份代码。

配置与状态**会被清空**（同名插件重新导入视为一份干净的插件）。
这两者存在主程序的文档里、不在插件目录内，所以删目录与重写文件都带不走它们，
必须由导入流程显式清空——否则「导入别人的同名插件」会读到上一份的旧配置，
包括已经失效的 token 或指向错误会话的目标，那种错配极难排查。

导入完成后，**如果这个插件在导入前本来是跑着的，会被自动重新启动**。
不恢复的话，「更新插件」这个动作会顺带把机器人弄成停机状态，
而用户很难联想到这是导入操作的副作用。

理由详见[配置与状态](config-and-state.md#用户能对配置做什么)。

## 导出时不含什么

| 内容 | 是否导出 | 原因 |
| --- | --- | --- |
| 源码文件 | ✅ | |
| `data/` 目录 | ❌ | 是运行时数据，可能很大，且分享给别人没有意义 |
| 配置值 | ❌ | 可能含 API Key，不该跟着插件包流传 |
| 插件状态 | ❌ | 同上，且它是设备相关的 |
