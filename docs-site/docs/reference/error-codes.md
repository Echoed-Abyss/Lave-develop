# 错误码与处置

本页只列**用户会实际碰到**的错误码，按「你该做什么」组织，而不是照抄官方全表。
官方完整表见[官方文档知识库](official-notes.md)。

## 网关关闭码

完整处置表见 [网关连接](../guide/gateway.md#关闭码处置)。最常遇到的三个：

| 码 | 含义 | 你该做什么 |
| --- | --- | --- |
| **4014** | intent 无权限 | 去「设置 → 事件订阅范围」关掉可选位，并确认平台权限已开通 |
| **4009** | 连接过期 | 会自动 Resume 重连，无需操作 |
| **4006** | session 无效 | 会自动改走 Identify 重新鉴权，无需操作 |

## 消息发送

| 错误码 | 官方含义 | 处置 |
| --- | --- | --- |
| `304026` | MSG_ID 回复的消息 id 错误 | 确认回复时用的是消息事件的 `d.id`（本项目已由 `PassiveCredential` 保证） |
| `304027` | MSG_EXPIRE 回复的消息过期 | 群聊窗口只有 5 分钟，超时即失效；本项目会自动改发主动消息 |
| `304028` | MSG_PROTECT 非 At 当前用户的消息不允许回复 | 群聊里只能回复 @机器人 的那条消息 |
| `304016` | SEND_ERROR 发消息错误 | 看 `trace_id` 找平台协助 |
| `304018` | SESSION_NOT_EXIST 机器人没连上 gateway | 先确认网关在线，再发消息 |
| `304020` | FILE_SIZE 文件大小超限 | 压缩后重发 |
| `304022` | PUSH_TIME 推送消息时间限制 | 主动消息有时间窗限制 |
| `304031` | 私信已关闭 | 用户关闭了接收 |
| `304082` / `304083` | 发送接口特有错误 | 见知识库 |
| `22009` | msg limit exceed 消息发送超频 | 降低频率；主动消息受独立频控 |
| `40034005` | 回复消息 `msg_id` 已过期 | 请在收到消息后尽快回复 |
| `40034025` | 请求参数 `event_id` 无效 | 检查 `event_id` 是否正确 |
| `40034026` | 请求参数 `event_id` 已过期 | 请在收到事件后尽快回复 |
| `40034128` | 被动回复时间或次数超限 | 窗口 5 分钟 / 60 分钟、次数 5 次 / 4 次 |
| `40054005` | 消息被去重 | **每次请求使用不同的 `msg_seq`**（本项目自动递增） |
| `100001` | Too many requests | 降低调用频率后重试 |

!!! tip "4013 / 4014 与消息类错误码的区别"

    4013 / 4014 是**网关关闭码**（连接被关掉），
    40034xxx / 40054xxx 是**接口返回码**（请求被拒绝）。
    前者去查 intents，后者去查请求参数。

## 本项目自己的错误分类

错误被归一成几类，界面上的文案按类别生成：

| 类别 | 典型来源 | 是否值得自动重试 |
| --- | --- | --- |
| 网络错误 | 断网、DNS 失败、连接被重置 | ✅ |
| 超时 | 请求超过 `AppConfig.httpTimeout` | ⚠️ 超时**不代表请求没发出去**；重试前要考虑幂等（发消息要靠 `msg_seq`） |
| 鉴权错误 | 凭证失效、AppSecret 错误 | ❌ 会自动作废缓存并重新换取 |
| 请求参数错误 | 本地校验不通过 | ❌ 是代码/输入问题 |
| 限流 | 官方频控 | ✅ 退避后重试 |
| 协议拒绝 | 4013 / 4014 | ❌ 降级 intents 后重试一次 |

## 排障时最该带走的两样东西

日志条目里的这两个字段（点开日志详情能看到）：

- **官方错误码**：定位问题性质；
- **`trace_id`**：找平台协助时唯一有效的凭据——官方凭它查服务端日志。

「日志」页右上角的「复制诊断信息」会把它们一起导出（密钥已脱敏）。
